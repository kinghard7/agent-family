## 前言
过去一年，Anthropic 与金融、法律、软件、医疗等数十个行业团队合作落地 LLM 智能体系统。我们发现一条核心规律：落地效果最好的方案，并非依赖重型复杂框架，而是采用**轻量化、可组合、分层递进**的基础模式。

本文汇总客户落地与自研智能体的工程经验，提供一套可直接落地的 Agent 构建方法论，包含概念区分、基础组件、5大类标准工作流、自主智能体范式、落地原则、框架选型建议与行业实践附录。

## 一、什么是 Agent？工作流 Workflow 与自主智能体 Agent 核心区分
行业对 Agent 定义混乱，Anthropic 将所有自主交互系统统一归类为 Agentic Systems，并做明确架构二分：

| 类型 | 控制逻辑 | 核心特点 | 适用场景 |
| ---- | -------- | -------- | -------- |
| Workflow（工作流） | 代码预定义调用路径，LLM 仅执行分配步骤 | 输出稳定、可预测、易调试、成本可控 | 步骤固定、需求标准化、路径可枚举任务 |
| Agent（自主智能体） | LLM 动态自主规划流程、选择工具、调整执行顺序 | 高度灵活，适配开放性未知任务 | 复杂调研、开放式问题、无法提前枚举全部执行路径 |

### 关键落地准则
优先使用 Workflow；仅当固定流程无法覆盖需求时，再升级为自主 Agent，避免过度设计。

## 二、什么时候用 Agent / 什么时候不该用 Agent
### ✅ 适合引入自主 Agent 的场景
1. 任务开放、无固定执行步骤，无法提前拆解完整流程；
2. 需要多轮动态工具检索，根据中间结果实时调整搜索方向；
3. 多分支并行探索、存在大量信息缺口需要迭代补充；
4. 长周期多步骤复杂任务（市场尽调、代码开发、学术综述）。

### ❌ 不建议使用 Agent 的场景
1. 任务流程固定，可拆分为标准化串行/并行步骤（文案翻译、简单数据提取）；
2. 对响应时延、Token 成本有严格限制；
3. 需求简单，单轮增强 LLM（检索+工具）即可完成；
4. 要求输出 100% 稳定、可复现，不允许模型自主决策偏差。

## 三、框架使用时机与选型建议
1. **原型快速验证阶段**：可使用第三方 Agent 框架简化开发；
2. **生产上线阶段**：建议剥离重型框架，基于基础 LLM API、自定义工具封装实现；
3. 核心原因：框架多层抽象增加可观测性难度、故障定位困难、隐藏调度与成本逻辑；
4. 折中方案：框架仅用于业务原型，上线前重构为原生可组合工作流组件。

## 四、基础构建单元：增强型 LLM（Augmented LLM）
所有智能体/工作流的底层最小单元，在原生 LLM 基础上附加三类增强能力：检索工具、外部工具调用、短期/长期记忆。

### 核心能力
1. 模型自主生成搜索关键词、筛选可用工具、自主判断存储/丢弃信息；
2. 标准化工具交互方案：Model Context Protocol（MCP），统一对接第三方工具生态；

### 落地实现两点要求
1. 针对业务场景定制工具、检索、记忆逻辑，不使用通用模板；
2. 为 LLM 提供清晰、完整文档化的工具接口（ACI，Agent-Computer Interface）。

## 五、五大标准 Workflow 工作流模式（可自由组合复用）
### 5.1 提示链 Prompt Chaining
1. 机制：任务拆分为串行有序步骤，上一步输出作为下一步输入，中间可插入代码校验闸门（Gate）；
2. 优势：每一步提示词高度聚焦，降低单轮模型负担，可单独拦截错误输出；
3. 适用：清晰可拆分的线性任务（大纲撰写→正文生成→翻译→校对）；
4. 流程图逻辑：Step1 → 程序校验 → Step2 → 程序校验 → Step3 → 最终输出。

### 5.2 路由 Routing
1. 机制：输入分类分发至专用子流程/专用模型；
2. 两类典型路由：
   - 业务路由：客服问题区分退款、技术咨询、投诉；
   - 模型路由：简单查询路由轻量 Haiku，复杂任务路由 Sonnet/Opus；
3. 适用：任务类别区分度高、分类准确率可控的场景。

### 5.3 并行化 Parallelization
两大分支变体：
1. 切片 Slicing：任务拆分为互不依赖子任务并行执行，最后聚合结果；
   例：多维度行业数据同步检索、多维度内容评估；
2. 投票 Voting：同一任务多次独立运行，多结果交叉校验提升可靠性；
   例：代码漏洞审查、事实核查、降低幻觉概率；
3. 价值：提速、拓宽信息覆盖、多源交叉验证减少错误。

### 5.4 协调者-工作者 Orchestrator-Workers
1. 机制：主协调 LLM 拆解子任务，批量派发并行子工作单元执行，汇总全部结果交叉校验；
2. 对应前文多智能体研究系统底层架构；
3. 适用：大规模多分支深度调研、多文档整合分析。

### 5.5 评估者-优化者 Evaluator-Optimizer
1. 机制：生成模块输出初稿 → 评估模块打分、标记缺陷 → 优化模块迭代修正，形成反馈闭环；
2. 适用：高要求内容生成、代码自动调试、报告润色迭代；
3. 优势：无需人工介入，自动迭代优化输出质量。

## 六、自主智能体 Agent 范式（最高复杂度）
当所有工作流模式均无法满足需求时，使用完全自主 Agent：
1. LLM 自主完成全部流程：需求拆解、工具选择、调用顺序、迭代终止判断；
2. 无代码预设路径，每一轮执行策略由模型实时生成；
3. 配套强制护栏：最大迭代次数、工具调用限流、超时中断、成本阈值；
4. 风险：不可预测性高、Token 消耗不可控、故障复现难度大；
5. 管控手段：完整日志记录每一步规划、工具调用、中间输出，全链路可观测。

## 七、模式组合与自定义拓展
所有工作流单元无排他性，支持多层嵌套组合：
示例：路由 + 并行化 + 评估优化
1. 路由区分任务类型；
2. 复杂任务启用并行工作者多维度检索；
3. 检索结果进入评估优化闭环迭代完善报告。

## 八、构建有效 Agent 的三大核心原则
1. **保持简洁**：从最简单方案起步，仅在业务证明不足时新增复杂度；拒绝过度设计多层嵌套；
2. **保证透明**：完整暴露模型规划步骤、工具调用记录、中间输出，方便调试与用户信任；
3. **精心设计 ACI（智能体-计算机接口）**：
   - 工具描述清晰、参数直观、附带使用示例；
   - 完善工具测试，降低模型误用、调用失败概率。

## 九、总结
1. 智能体系统成功的关键不在于复杂架构，而在于匹配业务场景的最简方案；
2. 分层递进思路：单轮增强LLM → 固定工作流Workflow → 自主Agent；
3. 5类标准化工作流覆盖绝大多数企业落地需求，优先复用；
4. 生产环境弱化重型框架，基于原生API构建可观测、可控、低成本系统。

## 附录1：Agent 落地两大典型场景
### A. 智能客服系统
核心架构：路由 + 提示链
1. 路由区分咨询类型；
2. 提示链分步执行：信息提取→知识库检索→回复生成→合规校验；
3. 简单问题固定工作流，复杂纠纷启用轻量自主Agent多轮溯源。

### B. 代码开发智能体
核心架构：协调者-工作者 + 评估优化
1. 协调器拆解需求、拆分编码、测试、修复子任务；
2. 多工作单元并行读取代码库、执行编译、运行测试；
3. 评估模块检测报错，迭代优化代码直至通过用例。

## 附录2：工具提示工程最佳实践
1. 工具描述以LLM理解视角撰写，避免纯开发专业术语；
2. 限定工具入参格式，强制结构化入参减少解析错误；
3. 每个工具附带标准调用示例与错误返回示例；
4. 限制单轮工具调用数量，防止模型无限循环检索。
